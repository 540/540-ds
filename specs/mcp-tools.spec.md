# MCP tools

<!-- predictable:capability={"authors":["runner"],"backlog":false,"covers":["mcp/tools","mcp/piece-types.ts"],"created":"","guidelines":[],"id":"SPEC-263","lastModified":"","lastVerified":"","proseDigest":"02f9730d0ddd83a7","relatedSpecs":[]} -->
The 540-ds MCP server gives an AI agent a registry of read-only tools (mcp/tools/index.ts) to query the design system while it assembles a piece: get-design-guide, list-templates, get-rules, get-template, get-patterns, get-template-stops, list-components, search-components, get-component, get-component-docs, get-component-stories, get-tokens and search-images. Every listed tool is annotated read-only. get-design-guide returns src/docs/diseno.md without the note for editors. list-templates lists every piece type in PIECE_TYPES with what it is, its triggers and the tools that have data for it, and the pieceType enum of the template tools is taken from the same source (PIECE_TYPE_IDS). Only talks are served: any other piece type is refused. get-rules returns the talk rules, also when no pieceType is given. list-components filters by level. get-component returns props with their types, defaults and descriptions, finds parts and tag names, and suggests names when it finds none. get-component-docs returns the component's sheet in Markdown. get-component-stories includes story code only when asked. search-components finds components by meaning, in Spanish too. get-tokens filters by category and text. get-template gives the shell and the index of stops without their code. get-template-stops returns each stop's code with its helpers and sample assets, and reports ids it does not know. search-images finds photos by theme, applies filters and skips photos already used. get-patterns filters by need and points to stops.
