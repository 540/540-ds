The component prop vocabularies (each component's src/components/<level>/<Name>/types.ts) name the values a component's props may take and the values they take when not given. For a prop with a closed set of values, types.ts exports a readonly UPPER_SNAKE array of the allowed values, declared 'as const', and the prop's type is that array's element type: for example TEXT_TONES is ['primary', 'secondary'], BUTTON_VARIANTS is ['primary', 'outline', 'ghost'] and BUTTON_SIZES is ['md', 'sm']. Every such array is non-empty and holds no value twice. A types.ts exports at most one <NAME>_DEFAULTS, a plain object with the value each listed optional prop takes when it is not given: TEXT_DEFAULTS is {variant: 'body-m', tone: 'primary', as: 'p', wrap: 'auto', measure: 'none'} and BUTTON_DEFAULTS is {variant: 'primary', size: 'md', iconOnly: false}, and each of their values is one of the values its prop allows (for most components the object is typed 'satisfies Required<Pick<<Name>Props, …>>', which the type check enforces). The component falls back to its defaults when a prop is omitted, so a component given no value for such a prop renders the same HTML as when given its default; Text with no props renders a <p>. DIALOG_DEFAULTS, BLOCK_TITLE_DEFAULTS, CYCLE_DEFAULTS, SHEET_DEFAULTS, STEPS_DEFAULTS and TIMELINE_DEFAULTS are empty objects, and every other <NAME>_DEFAULTS has at least one entry. The types.ts of exactly nine components export no defaults: Question, Lists, Screenshot, Blobs, CardList, Metric, Schema, Heartbeat and Spotlight.
